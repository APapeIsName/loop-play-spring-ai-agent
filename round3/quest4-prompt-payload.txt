## 검증 결론 — *발제 2.6 체크포인트* 정확히 직접 증명

발제 *"2회차 DEBUG 로그에서 프롬프트 길이가 1회차보다 길어졌는지 눈으로 확인"* → **확인 ✓**

### 메시지 수 변화
- T1: 2 messages (SYSTEM + USER)
- T2: **4 messages** (USER + ASSISTANT + SYSTEM + USER)

### Memory 정체 — 발제 4.5 + 바이트코드 검증 모두 정합
- `MessageChatMemoryAdvisor.after()`가 USER + ASSISTANT만 저장
- T2 prompt에 *정확히 그 USER + ASSISTANT*가 끼어듦
- **ToolMessage 없음** (Memory 외부, ChatClient 내부 history에 별도)

### 1단계 발견 5 (+1200 토큰 미스터리) 정량 정합
- T1 입력 토큰: ~1115 (SYSTEM + Tool 스키마 + 1 USER)
- T2 입력 토큰: ~2400 (T1 + Memory 1턴 USER+ASSISTANT + Tool 응답 layer)
- 차이 ~1285 = Memory layer (~150) + Tool layer (~1100) — *4단계 토큰 분해와 일치*

## ChatRequest 구조 (Spring AI 1.0 ollama)

```java
ChatRequest[
  model: String                  // "qwen2.5"
  messages: List<Message>        // role + content (+ images + toolCalls)
  tools: List<Tool>              // Function descriptions
  options: Map<String, Object>   // {temperature, ...}
]

Message[
  role: SYSTEM | USER | ASSISTANT | TOOL
  content: String
  images: null  (지원되지만 unused)
  toolCalls: null  (Tool 호출 시 채움)
]
```

## 측정 인프라 주의

- `org.springframework.web.client=DEBUG` 로거가 *RestClient의 outgoing request body*를 출력
- `reactor.netty.http.client=DEBUG`는 *HTTP 연결 메타데이터* (URI, response status)만 — body 미출력
- `org.springframework.ai.chat.client=TRACE`만으로는 *raw HTTP body 미보임* (이전 시도)
- 측정 후 반드시 logger 복원 (로그 폭증)
